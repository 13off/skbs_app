# Аудит производительности и надёжности — 01.08.2026

## Область проверки

Проверены текущая архитектура Flutter-клиента, репозитории данных, кеши,
Realtime-инвалидация, кабинет сотрудника, рабочие смены и маршруты,
уведомления, MAX-интеграция, Edge Functions, SQL-миграции, RLS-политики,

Аудит выполнялся поверх предыдущего системного аудита от 23.07.2026. Уже

виртуализированные списки сохранены.

## Исправленные проблемы

### Повторные загрузки кабинета сотрудника

Главная, задачи и профиль могли почти одновременно вызывать один и тот же
`employee-task-cabinet`. Репозиторий не объединял активные запросы и не имел
короткого кеша.

Исправление:

- одинаковые активные запросы объединяются;
- результат кешируется на 15 секунд;
- ответ сохраняется под запрошенным и фактически разрешённым `employee_id`;
- ручное обновление всегда использует `forceRefresh`;
- изменение сотрудников или задач очищает этот кеш через общий координатор;
- очистка во время активного запроса защищена поколением кеша.

Это не меняет данные, навигацию или внешний вид. Убираются только дублирующие
сетевые и серверные операции.

### Непокрытые внешние ключи

Production Advisor обнаруживал внешние ключи без индекса в новых контурах:
смены и маршруты, чат, выплаты, подбор, CRM и вклад сотрудников.

Добавлены покрывающие индексы без изменения ограничений и данных. После
миграции контрольный запрос показывает `0` непокрытых внешних ключей.

Информационные предупреждения `unused_index` не использовались как основание
для удаления: база молодая, часть индексов защищает редкие операции удаления,
архивации и проверки внешних ключей.

### Фоновая нагрузка MAX-моста

MAX-бот сохраняет пятисекундную проверку исходящих сообщений. Ранее каждый
опрос:

- повторно читал интеграционный секрет из базы;
- повторно запускал очистку зависших отправок.

Сначала была проверена возможность кешировать секрет в памяти Edge Function.
Production-метрика показала, что холодные экземпляры делают такой кеш
недостаточно надёжным, поэтому временное решение было заменено stateless-
проверкой.

Итоговое исправление:

- Edge Function сравнивает SHA-256 присланного секрета с закреплённым хешем;
- сравнение хешей выполняется без обращения к базе и с постоянным временем;
- открытый текст секрета не хранится в репозитории;
- постоянно работающий процесс MAX-бота запрашивает очистку зависших отправок
  не чаще одного раза в минуту;
- обычная проверка очереди по-прежнему выполняется каждые 5 секунд;
- очередь, подтверждения доставки и анкеты кандидатов не изменены.

При плановой ротации MAX-секрета необходимо обновить его SHA-256 в Edge
Function одновременно с секретом бота. Исходник действующей функции хранится в
репозитории и проходит Deno check.

## Проверенные области без небезопасных изменений

- Текущие RLS и SECURITY DEFINER RPC оставлены без массовой переработки:
  интерфейсные скрытия не заменяют серверные проверки, а слепой отзыв прав
  нарушил бы действующие Edge Functions.
- Таблицы без пользовательских RLS-политик не открывались клиенту: часть из них
  является служебным контуром Edge Functions.
- Информационно «неиспользуемые» индексы не удалялись без достаточной истории
  реальной нагрузки.
- Премиальная анимация рабочей кнопки не упрощалась, поскольку это изменило бы
  утверждённый дизайн. Контроллеры и таймер уже корректно освобождаются.
- Частота MAX-доставки не снижалась.
- Мобильный release marker не изменялся, APK автоматически не выпускается.

## Контроль совместимости

Изменения не меняют:

- роли и разрешения;
- структуру экранов и маршрутов;
- бизнес-процессы сотрудников, табеля, задач и выплат;
- правила начала и завершения рабочего дня;
- внешний вид приложения;
- формат данных Edge Functions;
- установленную PWA и текущий мобильный клиент.

Добавлены регрессионные контрактные тесты для кеша кабинета сотрудника и
производительности MAX-моста. Полный PR Check выполняет анализатор, все
Flutter-тесты, release web-build, Deno check изменённой Edge Function и
проверку SQL-миграции.
