# Global Voice Tool Planner v15

v15 добавляет детерминированный серверный планировщик для одной голосовой реплики вида «найди/отфильтруй → выбери часть → подготовь действие».

## Поддерживаемые цепочки

### Табель
- «Найди тех, кто сегодня не вышел, и поставь им нули».
- «На Талнахе найди бетонщиков, которые не вышли, и первым двум поставь 0».
- «Найди тех, кто сегодня на работе, и первым трём поставь единицу».

Источник истины: `employees` + `attendance`. Прораб всегда ограничен назначенным объектом.

### HR
- «Найди кандидатов без ответственного и первым трём назначь Гену».
- «Найди кандидатов с неполным комплектом документов и напиши им, что нужно дослать документы».
- «Найди тех, кто вылетает завтра, и напиши им: быть в аэропорту заранее».
- «Найди тех, кто не ответил на последнее сообщение, и первым двум назначь Гену».

Источники: `recruitment_applications`, `recruitment_documents`, `recruitment_messages`, `recruitment_flights`.

Обязательный комплект для фильтра полноты: паспорт, регистрация, СНИЛС, ИНН, полис.

### Снабжение
- «Найди просроченные срочные заявки и первые две переведи дальше».
- «На Талнахе найди согласованные заявки и первую отметь заказанной».

Источник: `procurement_requests`; переход статуса всё равно валидируется существующим `buildProcurementStatus`.

## Безопасность
- Планировщик не выполняет `insert/update/delete`.
- Он только читает role/company/object-scoped данные и строит уже существующие action-типы.
- Любая запись выполняется прежними client coordinators после подтверждения и AI-аудита.
- Максимум 12 write targets на один голосовой план; более широкую группу нужно сузить.
- Неоднозначные объекты и позиции возвращают уточнение вместо угадывания.
- Сообщения кандидатам готовятся только при подтверждённом Telegram/MAX-канале.
- `plan` metadata диагностическая и не содержит entity IDs.

## Порядок маршрутизации
1. v14 action-trace follow-up.
2. v15 deterministic tool planner.
3. v13/v12 reference routers.
4. существующие одиночные deterministic intents.
5. semantic fallback.

Так явная новая команда «найди ... и сделай ...» не зависит от старого разговорного контекста и не перехватывается одиночным обработчиком раньше времени.
