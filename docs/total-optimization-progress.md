# Тотальная оптимизация AppСтрой — журнал выполнения

## Неприкосновенные контракты

Все пакеты этой программы обязаны сохранять без изменений:

- бизнес-логику и расчёты;
- роли, RLS, права и объектную изоляцию;
- маршруты, состав экранов и пользовательские сценарии;
- подписи, размеры, расположение элементов, отступы, цвета и типографику;
- форматы данных, RPC и Edge Function, если изменение контракта отдельно не согласовано;
- текущую совместимость Web/PWA, Android и desktop.

Каждый пакет выполняется отдельной веткой и проходит анализатор, тесты, release web-build и профильную проверку изменённого контура.

## Пакет 1 — синхронизация и кеши

Ветка: `agent/total-optimization-package-1`.

### Выполнено

1. Realtime-события от уже отключённого канала больше не могут инициировать обновление активной компании.
2. При непрерывном потоке событий сохранено объединение изменений, но доставка теперь ограничена максимальным окном 500 мс и не может бесконечно откладываться.
3. Кеш кабинета сотрудника очищается один раз, даже когда один пакет одновременно затрагивает сотрудников и задачи.
4. Добавлены регрессионные тесты для зависимостей кешей и новых защитных контрактов.

### Что намеренно не изменено

- перечень таблиц и доменов Realtime;
- TTL существующих предметных кешей;
- порядок серверных записей;
- ручное обновление и `forceRefresh`;
- UI, анимации и навигация;
- роли, JWT, RLS и SECURITY DEFINER RPC.

### Обязательная проверка перед слиянием

```text
flutter pub get
flutter analyze
flutter test
flutter build web --release
```

Дополнительно проверить:

- переход между компаниями при открытых рабочих вкладках;
- локальное изменение задачи с последующим Realtime-событием;
- серию быстрых изменений табеля и выплат;
- отсутствие двойной перезагрузки кабинета сотрудника;
- неизменность всех экранов светлой и тёмной темы.

## Следующие пакеты

1. Инструментальные замеры холодного и тёплого запуска, открытия вкладок и тяжёлых списков.
2. Аудит оставшихся eager-списков и перевод только подтверждённых длинных списков на ленивую отрисовку.
3. Аудит повторных запросов и точечное in-flight объединение без увеличения TTL.
4. Оптимизация превью изображений, файлов и экспортов с контролем памяти.
5. Анализ production-запросов и индексов только по фактической статистике.
6. Чистка dead code и зависимостей только после доказательства отсутствия использования и полного регресса.
